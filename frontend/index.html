Security Lab

Four ways an untrusted actor could attempt to corrupt credit state — and how the protocol deterministically blocks each vector on-chain.

01 REPLAY ATTACK
Reuse Consumed Evidence
BLOCKED
Submits previously verified evidence chunk a second time to inflate credit capacity maliciously.
Revert Reason: EvidenceAlreadyConsumed()
Error Selector: 0xae5c42ee
Enforcement: AttestcoinVerifier.sol
02 SOURCE SPOOFING
Unregistered Source Emitter
BLOCKED
Submits proof claiming an arbitrary unverified contract emitted economic volume for the merchant.
Revert Reason: SourceContractMismatch()
Error Selector: 0xd1ec97f1
Enforcement: AttestcoinVerifier.sol
03 REVERTED SOURCE TX
Failed Source Transaction
BLOCKED
Submits an included-but-reverted source receipt (status=0) attempting to claim credit for failed payments.

interface ICreditPassport {
    function getCreditCapacity(bytes32 merchantId) external view returns (uint256);
    function getCreditTier(bytes32 merchantId) external view returns (uint8);
    function getCurrentExposure(bytes32 merchantId) external view returns (uint256);
    function getAvailableCredit(bytes32 merchantId) external view returns (uint256);
    function getVerifiedEconomicActivity(bytes32 merchantId) external view returns (uint256 eventCount, uint256 paymentVolume);
    function getMerchantState(bytes32 merchantId) external view returns (tuple(
        uint256 verifiedEventCount,
        uint256 verifiedPaymentVolume,
        uint256 successfulRepaymentCount,
        uint256 repaymentVolume,
        uint256 repaymentStreak,
        uint256 missedObligations,
        uint64 lastVerifiedActivity,
        uint256 currentExposure,
        uint256 currentCapacity
    ));
}
